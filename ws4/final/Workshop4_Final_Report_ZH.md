# Workshop 4：策略梯度期末报告

作者：Zhengnan Cao, Yuchen Yang

本报告合并 Task 1 与 Task 2，统一采用修正版 PG 实验。除另有说明，训练种子为 0、1、2；每检查点用 10000-10009 十个固定种子评估随机策略，评估随机流与训练隔离。曲线为三个训练种子的均值及一倍样本标准差，不是置信区间；评估步数不计入训练预算。

## Task 1 - Question 1：InvertedPendulum 环境

### 问题

环境的状态空间、动作空间和奖励分别是什么？它们有限还是无限、离散还是连续？环境是确定性还是随机性？

### 回答

| 项目 | 定义与分类 |
|---|---|
| 状态／观测 | 小车位置、摆杆角度、小车速度、摆杆角速度；四维连续坐标，观测 Box 无界，可能取值无限。 |
| 动作 | 一维小车施力指令，范围 [-3, 3]；连续、有界，但可能取值无限。 |
| 奖励 | 有限离散值：健康转移后为 1，导致终止的转移为 0；1000 步时间限制使回合总回报不超过 1000。 |

已核对安装的 Gymnasium 1.3.0：观测含非有限数值或摆角绝对值大于 0.2 弧度时终止；TimeLimit 在 1000 步截断。给定完整仿真状态和动作，物理转移是确定的；重置时加入均匀随机噪声，因此初始状态随机，随机策略采样动作又引入额外随机性。

## Task 1 - Question 2：三种 PG 方法

### 问题

在 InvertedPendulum 上运行 Vanilla PG、Reward-to-go 和 Baseline，用 TensorBoard 可视化训练，判断是否训练成功并说明策略是否随机。

### 提交内容

下图按要求绘制评估回报与环境步数，比较学习率 0.001、最小 batch 1000、gamma 0.99、64 x 2 ReLU 网络下的三种方法。这里复用 Task 2 对应的九个修正版运行，不把它们另算为新实验；每次申请 500,000 训练步，完整末批次后的最终评估可能略超预算，图中曲线则止于 500,000。

![Task 1：三种 PG 方法比较](figures/task1_q2_methods.png)

这些运行启用了 TensorBoard 日志；图中曲线根据 CSV 中的评估标量重建。事件文件核验不代表已在浏览器查看。

### 讨论

**学习曲线是否表明训练成功？**

三种方法都有改善，最终评估回报依次为 Vanilla 141.5 ± 13.6、RTG 536.3 ± 69.3、Baseline 201.8 ± 20.9。但没有一种配置达到连续三次评估均值至少 950 的标准，因此能够说明发生了学习，不能据此宣称任务已解决。

**策略是确定性的还是随机性的？**

策略是随机的：高斯 actor 在训练和评估时均采样动作，仅环境执行的动作进行边界裁剪。固定评估种子使这些采样回合可复现，不会把策略变成确定性策略。

## Task 2 - Question 1：学习率

### 问题

在 [0.00001, 0.01] 范围内比较至少三个学习率 α，并研究它与 Reward-to-go、Baseline 的交互作用。

### 提交内容

三个面板分别给出各方法在学习率 0.0001、0.001、0.01 下的评估曲线；最小 batch 为 1000，其余公共设置与 Task 1 相同。

![Vanilla、RTG 和历史均值 Baseline 的学习率比较](figures/task2_q1_learning_rates.png)

单元格为各种子末五次评估回报均值的跨种子均值 ± 标准差。

| 方法／学习率 | 0.0001 | 0.001 | 0.01 |
|---|---:|---:|---:|
| Vanilla | 43.9 ± 5.9 | 106.1 ± 19.9 | 351.7 ± 305.2 |
| RTG | 66.2 ± 7.6 | 457.7 ± 45.8 | 452.6 ± 438.1 |
| Baseline | 52.4 ± 7.1 | 149.1 ± 24.0 | 700.7 ± 465.2 |

RTG 包含外层 gamma 的时间步次幂，使折扣从回合起点计量。Baseline 为所有先前 batch 中各轨迹折扣回报的等权历史均值，初始为零，不是当前 batch 均值或学习到的价值函数。核心实验使用 Adam，不启用优势标准化、GAE 或梯度裁剪。

### 讨论

**哪个学习率收敛最快？**

按连续三次评估均值至少 950 的标准，学习率 0.01 是最快出现成功确认的设置：RTG 有 2/3 种子达标，成功种子的条件中位确认步数为 225,451；Baseline 为 2/3、320,296.5 步。Vanilla 仅 1/3 在 500,249 步确认，已超过标称 500,000 步预算；更低学习率均未达标，而且达标后仍可能退化。

**学习率如何与 RTG、Baseline 交互？更高学习率会放大还是削弱其效果？**

学习率由 0.001 增至 0.01 时，RTG 相对 Vanilla 的末五次回报优势从 351.6 降为 100.8，Baseline 的优势则从 43.0 增为 349.0。因此交互作用取决于方法，更高学习率没有统一放大降方差方法的表现优势，较大的种子间变异也不支持普遍排名。

**这种效果是否与策略梯度方差有关：大步长会放大噪声，还是在降低方差后加快学习？**

较大学习率可能放大含噪参数变化，这与 0.01 曲线的不规则波动和较大种子间差异相符，同时它也更早出现阈值确认。下一题的固定策略诊断支持 RTG、Baseline 在该点具有较低梯度方差，但没有测量整个训练过程，也不能证明噪声是学习差异的唯一原因；Adam 还会缩放更新。

## Task 2 - Question 2：每批采样步数

### 问题

为 Vanilla PG、Reward-to-go 和 Baseline 分别比较至少三个 batch steps，分析回报、样本效率和梯度方差。

### 提交内容

按要求提供三张图，每种方法分别比较最小 batch 1000、2000、5000，学习率固定为 0.001。各运行申请 500,000 步并完成完整轨迹，实际总步数可能略超预算；最终回报取最后保存的评估，曲线积分只到标称预算。

![Vanilla PG：三种 batch 大小](figures/task2_q2_batch_vanilla.png)

![Reward-to-go：三种 batch 大小](figures/task2_q2_batch_rtg.png)

![历史均值 Baseline：三种 batch 大小](figures/task2_q2_batch_baseline.png)

### 讨论

**固定环境步数时，增加 batch steps 是否始终提高最终评估回报？**

不会：batch 从 1000 增至 2000、5000 时，最终回报均值依次下降，Vanilla 为 141.5 → 95.9 → 90.2，RTG 为 536.3 → 141.9 → 101.4，Baseline 为 201.8 → 130.1 → 100.8。因此这些设置下，单次更新采样更多并未改善最终回报。

**梯度方差降低、每次更新计算增多的权衡，如何体现于样本效率？**

batch 从 1000 增至 5000 后，Vanilla、RTG、Baseline 平均更新次数分别从 474.7、450.3、469.0 减至 100；预算归一化 AUC 回报也分别从 84.1 降至 47.8、177.6 降至 57.2、102.2 降至 51.8。较大 batch 在局部诊断中方差较低，但 AUC 也较低；更新次数减少可能是原因之一，本实验尚未隔离这一因果关系。并发运行耗时不能用于严格比较计算速度。

**大 batch 对两种降方差方法的降幅是否与 Vanilla 一样强？哪种方法获益最小？**

以 batch 1000 到 5000 的梯度协方差迹相对降幅定义收益，两种方法在该固定策略下的降幅均强于 Vanilla，但**两种降方差方法中 Baseline 获益较小**：74.0%，小于 RTG 的 76.2%。

| 估计器 | batch 1000 方差迹 | batch 5000 方差迹 | 相对降幅 |
|---|---:|---:|---:|
| Vanilla | 0.4381 | 0.1286 | 70.7% |
| RTG | 0.0840 | 0.0200 | 76.2% |
| Baseline | 0.1162 | 0.0302 | 74.0% |

该独立诊断在同一固定初始策略下采集 20 组独立配对轨迹，各 batch 为完整轨迹的嵌套前缀。Baseline 来自独立 5003 步校准批次且保持固定，这些采样不计入正式训练预算；结果条件于该策略与校准值，有限重复、随机批长及按步平均限制了普遍性和严格无偏解释，不能证明整个训练过程具有同一排名。

## Task 2 - Question 3：CartPole 上的 PG 与 DQN

### 问题

在 CartPole 上运行 PG，调整训练预算、batch steps、学习率、gamma、网络规模等超参数，并与 DQN 比较学习速度。

### 提交内容

两种方法均使用三个种子、200,000 步申请预算、64 x 3 ReLU 网络及 gamma 0.99。PG 重新训练，DQN 复用 WS3 基准；seed 0 调参选择了 PG 的方法、学习率和 batch，正式组复用该种子可能使选择受益。

| 设置 | PG | DQN |
|---|---|---|
| 方法；评估动作 | RTG；随机 | DQN；贪心 |
| 学习率；batch | 0.003；2000 个新采样步 | 0.001；batch 64 |
| 回放／更新设置 | 新的同策略批次 | 容量 100,000；warm-up 1000；每 500 次更新同步目标网络 |

剔除 200,000 步之后的观测，线性插值使用共同有数据支持的终点 **190,831 步**，不外推；AUC 在共同的 10,000 步网格上积分，并包含该终点。

![CartPole：PG 与 DQN 评估回报](figures/task2_q3_pg_vs_dqn.png)

### 讨论

**哪个算法收敛更快？学习速度差异可能来自哪里？**

DQN 三个种子均连续三次评估均值至少 475，中位确认步数为 60,000，PG 为 0/3；DQN 的 AUC 也更高，为 298.8 ± 36.5，PG 为 248.1 ± 27.5。相较于重新采集同策略批次，经验回放复用和频繁更新可能提高样本效率。调参配置及贪心／随机评估不同，不能把差异完全归因于更新规则，而且达标确认不保证之后始终稳定。
