## Installation

Use Python 3.10. The entry points were checked with Python 3.10.21, PyTorch 2.5.1+cu121, Gymnasium 1.3.0, NumPy 2.2.6 and MuJoCo 3.15.0 in the existing coursework environment. The dependency files retain the recorded version pins; they are not a platform-independent lockfile.

From this `code` directory, create and activate an environment, then install the shared requirements:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

The shared requirements cover CartPole and MuJoCo environments, including optional video utilities. Each workshop also retains its original `requirements.txt` for separate installation. A CPU run is sufficient for all entry points. GPU SAC requires a CUDA-enabled PyTorch installation compatible with the local GPU and driver.

## Outputs and evaluation

Use `--output_dir runs/<unique-name>` for every run. Existing nonempty output directories are rejected. Training saves configuration, scalar metrics, evaluation CSVs, a summary and an inspection checkpoint. TensorBoard is optional for WS3 (`--tensorboard`) and enabled by the PG and SAC runners.

Evaluation happens automatically during training in separate environments. The report protocol uses ten evaluation episodes, with seeds 10000-10009, every 10000 training steps. DQN evaluation is greedy; PG and SAC evaluation is stochastic. Evaluation steps are excluded from training budgets. PG/GAE completes whole episodes and batches, so actual training steps can exceed the requested budget.

To view events, run this from the relevant workshop directory:

```powershell
python -m tensorboard.main --logdir runs
```

Checkpoints support policy inspection, not exact training resumption: replay buffers and complete simulator states are not saved. Use `--render` for an interactive training window or `--log_video` for optional policy video output. Headless training does not require either option.

## Source and experiment provenance

The algorithm directory layouts, entry points and completed implementations are retained from the existing final code packages. WS5 comments and two module docstrings were translated to English. Executable Python ASTs were checked against the originals; algorithm behavior was not changed during organization.

The WS3/WS4 submission code is a template-preserving port of the archived experimental implementation. WS5 formal experiments used a frozen source snapshot. The report's saved measurements were not regenerated by this packaging task. Raw runs, trained weights, videos, caches and historical planning documents are excluded from this source package and remain in the original coursework evidence directories.

The inherited `utils/log_utils.py` files are inactive teaching references containing unfinished legacy rollout examples. Active runners use `utils/util.py` and, for SAC evaluation, `utils/evaluation.py`. The legacy examples are not runnable entry points and do not require installing old Gym for the active training commands.

## Verification
